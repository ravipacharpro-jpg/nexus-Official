# Design Document Skill

## When to use
- Starting a new feature or project
- Writing an RFC or PRD
- Documenting architecture decisions

## Structure

### 1. Context
- Problem statement
- Goals and non-goals
- Constraints

### 2. Options considered
- Option A: ... (pros/cons)
- Option B: ... (pros/cons)
- Chosen option and why

### 3. Design
- API/schema changes
- Data model changes
- Flow diagrams
- Edge cases

### 4. Risks
- Technical risks
- Operational risks
- Mitigations

### 5. Rollout
- Phased rollout plan
- Rollback strategy
- Success metrics

### 6. Open questions
- Things to decide later
- Dependencies on other teams

## Output format
Markdown document following the above structure. Use tables for options and risks. Include diagrams where they clarify the design.
